# Redaction Checklist

Use this before turning private experience into public teaching material.

## Quick Decision

```text
What is the public lesson?

Can the lesson survive if all private details are removed?

If no, do not publish.
```

## Remove These

- [ ] Real client, partner, staff, student, or buyer names.
- [ ] Email addresses, phone numbers, account IDs, keys, tokens, passwords.
- [ ] Local machine paths and private folder names.
- [ ] Private repo names, branch names, commit references, or issue links.
- [ ] Exact operational, financial, factory, sales, or payment numbers.
- [ ] Screenshots from private tools.
- [ ] Personal notes, career notes, health notes, or family details.
- [ ] Commercial strategy or internal product design.

## Replace With These

| Private detail | Public replacement |
|---|---|
| real person | "the user" |
| real company | "a small team" |
| real path | "your project folder" |
| real data | fake sample table |
| real dashboard | plain checklist |
| exact number | fake rounded number |

## Public Lesson Shape

```text
From building local tools, one reusable lesson is:
[lesson]

Fake example:
[fake example]

Try this:
[reader action]

Check before publishing:
[safety check]
```

## Final Pass

- [ ] The draft helps without naming the original project.
- [ ] All examples are visibly fake.
- [ ] No sensitive detail remains.
- [ ] No external claim needs verification.
- [ ] Tone is useful, not boastful.
