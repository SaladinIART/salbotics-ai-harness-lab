# Underdog Racing Tutorials

This tutorial path explains what we learned while building **Underdog**, a
top-down pixel racing prototype built with Phaser + TypeScript.

The point is not only the game. The point is the working method:

```text
small checkpoint -> playable evidence -> critique -> next checkpoint
```

## Tutorial Path

1. [Harness a Big Game Idea Without Drowning](tutorial-01-harness-a-big-game-idea.md)
2. [Racing Feel Before Racing Features](tutorial-02-racing-feel-before-features.md)
3. [Progression, Difficulty, and Fair Pressure](tutorial-03-progression-difficulty-fair-pressure.md)
4. [Playtest Evidence Beats Vibes](tutorial-04-playtest-evidence.md)
5. [Wisdoms From the Exercise](wisdoms-from-underdog.md)

## What You Should Learn

- How to turn an ambitious game idea into checkpoints.
- Why physics feel must come before campaign complexity.
- Why rendering and simulation should stay separate.
- How visible feedback, such as tire angle and speed, improves playfeel.
- How difficulty should be explicit, saved, and testable.
- How browser smoke tests catch crashes that unit tests cannot.

## Recommended Use

Read one tutorial, then inspect the matching files in `src/` and `tests/`.
This makes the lesson concrete instead of inspirational-only.
