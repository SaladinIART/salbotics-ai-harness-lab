# Tutorial 1: Harness a Big Game Idea Without Drowning

## Goal

Learn how Underdog went from an ambitious racing fantasy into a sequence of
small checkpoints that could be built, tested, and improved.

## The Original Temptation

The idea was huge:

- street racing
- bicycles, motorcycles, cars, F1
- tournaments
- money
- car upgrades
- driving skills
- sponsors
- team management

That is exciting, but also dangerous. A big idea can make the first version so
large that nothing becomes playable.

## The Harness Move

We reduced the fantasy into this checkpoint path:

```text
CP1 research docs
CP2 Phaser scaffold
CP3 time-trial physics lab
CP4 garage upgrades
CP5 campaign shell
CP6 one-rival duel
CP7 championship loop
post-CP7 polish and playfeel
```

Each checkpoint had a master list and done criteria. That made the project
reviewable.

## What Changed

Instead of asking, "Can we build the whole racing game?"

We asked:

```text
What is the smallest next checkpoint that teaches us something real?
```

That question saved the project from becoming a pile of disconnected systems.

## Copy-Ready Prompt Card

```text
I want to build an ambitious game, but do not let me build everything at once.
Create a checkpoint plan where each checkpoint has:
- a small playable or reviewable result
- a master list
- done criteria
- test plan
- what must not be included yet

Prioritize learning and playability over feature count.
```

## Common Failure

**Failure:** Adding campaign, AI, upgrades, and physics all at once.

**Fix:** Build handling first. Then upgrades. Then rivals. Then championship.

## Recap

Harness engineering does not shrink your dream. It gives the dream a staircase.
